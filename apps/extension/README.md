# Fuzzy — Chrome Extension (Manifest V3)

**Fuzzy** is the shipped name of the extension. `MyKid` remains the
repository and Python-package name.

Fuzzy blurs scary, gory and grown-up pictures and videos as a child
browses. Everything runs on the device — no image, URL or page content
ever leaves the browser (audited: `docs/12-privacy-and-limitations.md`).

**What it detects:** gore/violence and sexual content at the scene level
(whole-image blur), plus knives and scissors as regions. **What it does
not:** firearms, drugs, self-harm, hate symbols, or anything needing text
or audio.

**Detection accuracy on harmful content is unmeasured** — there is no
harmful evaluation set in this project. Safe fixtures only establish that
it doesn't fire indiscriminately.

## First-time setup

Two things the extension needs are intentionally **not** committed to git —
a 10MB+ model file and a third-party wasm runtime, both regenerable:

```bash
node apps/extension/scripts/setup.js
```

This copies `models/yolo11n.onnx` from the project root and fetches the
`onnxruntime-web` wasm runtime into `vendor/`. Re-run it if the model or the
pinned `onnxruntime-web` version changes.

## What's here

| File | Purpose |
|---|---|
| `manifest.json` | MV3 manifest — content script, popup, background worker, `web_accessible_resources` for the model/runtime, wasm-permitting CSP |
| `src/content/content-script.js` | Injected into every page. Counts `<img>`/`<video>` elements and asks the background service worker to run its self-test once per page load. No DOM mutation, no inference code of its own. |
| `src/background/service-worker.js` | Thin router: ensures the offscreen document exists and relays self-test requests to it. Does **not** run inference itself — onnxruntime-web needs dynamic `import()`, which the HTML spec disallows inside a service worker. |
| `src/offscreen/` | Hidden extension-owned page where onnxruntime-web + the model actually load and run. A normal DOM/Window context (unlike the service worker) that still runs under the extension's own CSP (unlike a Worker spawned from the content script, which real sites' CSP can block). See docs/11 for the full debugging trail that led here. |
| `src/popup/` | Toolbar popup — shows element counts and the detection-engine self-test status (model load time, inference time, output tensor shape). |
| `vendor/onnxruntime-web/` | *(gitignored, generated by setup.js)* wasm-only onnxruntime-web build — single-threaded by design, since multi-threaded wasm needs cross-origin isolation headers this extension can't guarantee on arbitrary sites. |
| `models/` | *(gitignored, generated by setup.js)* copy of `../../models/yolo11n.onnx` — extensions can't reference files outside their own loaded folder. |
| `assets/icons/` | Placeholder icons. |

## Load it locally

1. Run the setup step above if you haven't already
2. Open `chrome://extensions`
3. Enable **Developer mode** (top right)
4. **Load unpacked** → select this `apps/extension/` directory
5. Open any page (including youtube.com) and click the MyKid toolbar icon — after the page finishes loading, the popup should show image/video counts plus "Detection engine: ready" with load/inference timings and an output tensor shape

If the popup says "MyKid isn't active on this page", that's expected on `chrome://` pages, the Web Store, and any tab that was open *before* you loaded/reloaded the extension (content scripts only attach on page (re)load).

If "Detection engine: failed (...)" shows up, that's the signal to debug this phase — check the page's own devtools console (`F12`) for the `[MyKid]` log lines, which include the underlying error.
